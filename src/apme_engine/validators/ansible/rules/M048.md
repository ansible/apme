## Prefer builtin module (M048)

Uses `ansible.plugins.loader.module_loader.find_plugin_with_context()` in the
session venv to detect when an already-FQCN module resolves outside
`ansible.builtin` / `ansible.legacy`, but the same short name still resolves
as a real `ansible.builtin.*` plugin. Suggests the builtin FQCN so playbooks
prefer core modules over collection duplicates (e.g. `community.general.copy`
→ `ansible.builtin.copy`).

Unlike the static-list L030 graph rule, this check is authoritative against the
installed ansible-core — not `builtin-modules.txt`. Modules that left core for
a collection (e.g. `mount` / `sysctl` → `ansible.posix` only) are not flagged,
because the short name no longer resolves to `ansible.builtin.*`. When L030 is
retired (see PR #715 / issue #714), M048 remains the prefer-builtin path.

Short module names (no FQCN) are owned by **M001**. Community collection
guidance without a builtin twin remains **L005**.

### Example: violation

```yaml
- name: Example play
  hosts: localhost
  connection: local
  tasks:
    - name: Copy via community collection
      community.general.copy:
        src: /tmp/a
        dest: /tmp/b
```

### Example: pass

```yaml
- name: Example play
  hosts: localhost
  connection: local
  tasks:
    - name: Copy with builtin
      ansible.builtin.copy:
        src: /tmp/a
        dest: /tmp/b

    - name: No builtin twin (left core)
      ansible.posix.mount:
        path: /mnt/data
        src: /dev/sdb1
        fstype: xfs
        state: mounted

    - name: No builtin twin
      community.general.timezone:
        name: UTC
```
