## Argspec validation — docstring (L058)

Parses each module's `DOCUMENTATION` string (via `ansible.utils.plugin_docs.get_docstring`) to extract the argument specification, then validates user-supplied parameters against it. The target module source is parsed without importing it, but resolving documentation fragments can import fragment plugin code; do not use this check with untrusted collections. The result is fast but may drift from the actual `argument_spec` defined in code.

Checks: unsupported parameters, missing required parameters, invalid choices.
Arguments include inherited play, block, and task `module_defaults`, including
defaults inherited through roles and task includes/imports. Later entries replace
the earlier mapping for the same module/group; `{}` clears that entry. Matching
action groups apply before module defaults, followed by explicit task arguments.
Ansible's parameter-alias precedence is applied to the combined arguments.

Group names, historical aliases, extended groups, and module redirects are
resolved from installed metadata in the selected Ansible environment. Defaults
names ignore `collections`; task module resolution respects its collection context.
Distinct invocations of shared content are checked separately. Missing metadata,
templated parameter mappings, and assessment limits produce an L058 warning
explaining incomplete argument checks. Literal invalid defaults produce errors.
The resolver never evaluates Jinja, runs a playbook, or loads project plugins.
Defaults-related findings require manual review so a task-only fix cannot alter
defaults authored in an enclosing scope.

Literal argument names/values remain checked alongside Jinja values. Dynamic
values skip choice checks and may become `omit`, so they cannot establish definite
presence for unsupported-argument or argument-group errors. A templated task-level
`args` mapping remains unassessable.
For tasks without defaults, short module names whose search order includes custom
collections remain skipped; fully qualified names are checked.

### Example: violation

```yaml
- name: Example play
  hosts: localhost
  connection: local
  tasks:
    - name: Bad args
      ansible.builtin.file:
        path: /tmp/foo
        invalid_param: true
```

### Example: pass

```yaml
- name: Example play
  hosts: localhost
  connection: local
  tasks:
    - name: Good args
      ansible.builtin.file:
        path: /tmp/foo
        state: touch
```
