## FQCN resolution (M001)

Uses ansible-core's action and module plugin loaders in the session venv to
resolve names against the installed core version, collection metadata and task
collection search order. Action-only plugins are supported. Aliases and
redirects are read from the installed content rather than a maintained mapping.

Before offering a rewrite, the resolver checks that the qualified spelling
selects the same action and module plugin files as the original. Builtins
normally use `ansible.builtin`; local overrides use `ansible.legacy` when that
preserves both selections. Project-local content is considered only when
`APME_ANSIBLE_TRUST_PROJECT_CODE` is enabled.

The verified target is carried in `resolved_fqcn` and shared with L026 findings
for the same task during remediation. The transform preserves arguments,
comments and `action` / `local_action` syntax. Names without a verified target
stay for manual review, with a diagnostic when a qualified spelling would
change the plugin selection. An unavailable plugin is reported by L037.

Resolution results are cached by core version, collection inventory and search
context. Trusted project content is resolved afresh because local files may
change without a version bump.

### Example: violation

```yaml
- name: Example play
  hosts: localhost
  connection: local
  tasks:
    - name: Uses short name
      yum:
        name: httpd
        state: present
```

### Example: pass

```yaml
- name: Example play
  hosts: localhost
  connection: local
  tasks:
    - name: Uses FQCN
      ansible.builtin.dnf:
        name: httpd
        state: present
```
