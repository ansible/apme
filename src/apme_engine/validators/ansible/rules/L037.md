## Unresolved module (L037)

Reports a task module name when ansible-core's module and action plugin loaders
cannot resolve it in the scan environment. Resolution uses the task's in-scope
`collections` search order. By default, introspection runs from a private
working directory with an empty Ansible config, so the scan root's
`ansible.cfg` and local plugin paths are not loaded. This keeps project
controlled plugin code from running in the validator process.

For content that an administrator trusts, set
`APME_ANSIBLE_TRUST_PROJECT_CODE=true` in the Ansible validator environment to
allow project-level `ansible.cfg` and plugin paths during introspection. Those
paths can load and execute Python code; enable this only for trusted content.
Role-specific plugin paths are not inferred for each task. Removed modules are
reported as M004 instead.

### Example: violation

```yaml
- name: Typo in module
  ansible.builtin.copyyy:
    src: a
    dest: /tmp/b
```

### Example: pass

```yaml
- name: Copy file
  ansible.builtin.copy:
    src: a
    dest: /tmp/b
```
