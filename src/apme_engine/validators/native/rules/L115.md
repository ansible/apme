## Molecule configuration (L115)

Validate configuration YAML, duplicate keys, and the effective configuration against the selected bundled legacy or native schema. Shared `.config/molecule/config.yml` settings are merged before scenario overrides. Unknown keys are reported at their source. Native `ansible:` configuration and shared state are assessed automatically.

Enabled automatically; default severity is medium (warning). Existing APME rule
configuration can change severity or disable the finding. Configuration findings
require manual review and are not sent to a task remediation transform.

Compatibility target: Molecule 24.9.0+. Legacy and native configuration use
bundled 24.9.0 and 26.11.0 profiles respectively, selected from merged supplied
configuration. Profiles describe syntax compatibility, not vendor support for
every upstream release or driver.

Examples below are uploaded snapshot maps: each key is a relative file path and
each literal value is that file's contents. The native Molecule validator checks
these files directly, without wrapping configuration as an Ansible playbook.

### Example: violation

```yaml
molecule/default/molecule.yml: |
  provisioner:
    name: unsupported
```

### Example: pass

```yaml
molecule/default/molecule.yml: |
  provisioner:
    name: ansible
```

For a directory assessment, include the shared config and referenced files.
A single-file assessment cannot establish whether references exist outside its
snapshot. See [Molecule validation guide](../../../../../docs/guides/MOLECULE.md).
