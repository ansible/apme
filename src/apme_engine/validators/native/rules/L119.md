## Molecule playbooks (L119)

Inspect referenced Ansible playbooks for malformed YAML and missing play/import structure. Ansible YAML tags and Jinja are treated as data. Existing graph and Ansible rules retain their IDs; this rule covers structure even when a playbook cannot enter the graph.

Also checks `module_defaults` mapping/name shapes at play, role declaration,
block, task, and include `apply` scopes. Empty module mappings, ordered lists of
mappings, and templated parameter mappings are accepted. Module names must be static. This
structural check does not resolve action groups or module argument specs;
L058/L059 perform those checks using the selected Ansible environment.

Enabled automatically; default severity is medium (warning). Existing APME rule
configuration can change severity or disable the finding. Configuration findings
require manual review and are not sent to a task remediation transform.

Compatibility target: Molecule 24.9.0+. Legacy and native configuration use
bundled 24.9.0 and 26.11.0 profiles respectively, selected from merged supplied
configuration. Profiles describe syntax compatibility, not vendor support for
every upstream release or driver.

Examples below are uploaded snapshot maps: each key is a relative file path and
each literal value is that file's contents. Both snapshots explicitly reference
the supplied playbook so structural validation runs even for invalid play YAML.

### Example: violation

```yaml
molecule/default/molecule.yml: |
  provisioner:
    playbooks:
      converge: converge.yml
molecule/default/converge.yml: |
  - name: A task without a wrapping play
    ansible.builtin.debug:
      msg: example
```

### Example: pass

```yaml
molecule/default/molecule.yml: |
  provisioner:
    playbooks:
      converge: converge.yml
molecule/default/converge.yml: |
  - name: Converge
    hosts: all
    tasks: []
```

For a directory assessment, include the shared config and referenced files.
A single-file assessment cannot establish whether references exist outside its
snapshot. See [Molecule validation guide](../../../../../docs/guides/MOLECULE.md).
